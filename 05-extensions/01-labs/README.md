# Engineering Labs

[Part 5](../README.md) · [Setup](../setup.md) · [Progress](../progress.md)

Repair unfamiliar code and data work. Read the reproduction before modifying the implementation. Use the small supplied inventory fixtures; demonstrate a changed requirement, not only the original answer.

Follow these eight lessons in order. Read each guide, then concepts/syntax, assignment, progressive help and acceptance criteria. A lesson is a unit of work, not necessarily a calendar day. Commit commands are included in every guide.

| Lesson | Focus | Verification |
|---|---|---|
| [LAB01](01-joins/guide.md) | Repair a report with inflated totals | Offline contract + evidence |
| [LAB02](02-api-change/guide.md) | Adapt a changed API contract | Offline contract + evidence |
| [LAB03](03-migration/guide.md) | Extend a schema without losing existing data | Offline contract + evidence |
| [LAB04](04-backfill/guide.md) | Repair missing backfill intervals | Offline contract + evidence |
| [LAB05](05-recovery/guide.md) | Repair a partial commit with a durable batch ledger | Offline contract + evidence |
| [LAB06](06-performance/guide.md) | Measure and improve dimension enrichment | Offline contract + evidence |
| [LAB07](07-logs/guide.md) | Interpret retries without reporting recovered runs as failures | Offline contract + evidence |
| [LAB08](08-handoff/guide.md) | Complete an independent maintenance ticket | Manual evidence |

## Exit check

A maintenance CLI with reproductions, regression tests, measured performance and a handoff. Demonstrate one successful run, one failure and recovery, one unfamiliar input and a clear English explanation. Record guided versus independent work honestly. Update only progress you have actually demonstrated.
